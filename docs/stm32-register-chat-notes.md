## 第 1 轮：什么是寄存器

**用户：**

以 `STM32F103VET6` 为例，给我解释一下什么是寄存器。

**助手：**

一句话先说清楚：

**寄存器就是芯片内部一小块“有固定用途、可直接读写”的高速存储单元。**

你可以把 STM32 想成一台机器，里面有很多功能模块：

- `GPIO`：控制引脚高低电平
- `USART`：串口通信
- `TIM`：定时器
- `RCC`：时钟控制

而寄存器，就是这些模块对外暴露出来的“控制面板”。

比如：

- 某一位写 `1`：打开时钟
- 某几位写成某个编码：把引脚设成输出
- 读某一位：看看串口数据是否收到了

在 `STM32F103VET6` 里，寄存器通常分两类：

1. **内核寄存器**
   这是 Cortex-M3 内核自己的寄存器，比如 `R0~R15`、`SP`、`PC`。
   它们主要给 CPU 执行指令时使用。

2. **外设寄存器**
   这是单片机开发里最常说的寄存器，比如 `GPIO`、`RCC`、`USART`、`TIM` 的控制寄存器。
   平时说“直接操作寄存器点灯”，大多指的是这类。

为什么寄存器重要？

因为 STM32 的硬件功能，最终都是靠寄存器控制的。

比如你想点亮一个 LED，不是对 LED 说“亮起来”，而是要一步步改寄存器：

1. 打开 GPIO 端口时钟
2. 配置该引脚是输入还是输出
3. 给输出寄存器写 `0` 或 `1`

也就是说：

**你写寄存器 = 你在给硬件下命令。**

用 `PC13` 这个引脚举例，常会用到这些寄存器：

- `RCC_APB2ENR`
  作用：给 GPIO 端口开时钟
- `GPIOC_CRH`
  作用：配置 `PC8~PC15` 这些引脚的模式
- `GPIOC_ODR`
  作用：控制输出电平
- `GPIOC_IDR`
  作用：读取输入电平

可以这样理解：

- `RCC_APB2ENR`：先给设备“通电”
- `GPIOC_CRH`：告诉设备“这个脚要干什么”
- `GPIOC_ODR`：真正输出高低电平
- `GPIOC_IDR`：读取当前脚上的状态

例如，开启 `GPIOC` 时钟：

```c
RCC->APB2ENR |= (1 << 4);
```

这句的意思是：

- `RCC->APB2ENR` 是 APB2 外设时钟使能寄存器
- 第 `4` 位控制 `GPIOC` 时钟
- `|= (1 << 4)` 就是把这一位置 `1`

效果就是：

**让 `GPIOC` 外设开始工作。**

如果时钟没开，后面再去配 `GPIOC`，通常都不会生效。

从地址角度理解，寄存器又可以看成：

**“有特殊含义的固定内存地址”**

比如某个寄存器地址是：

```c
0x40021018
```

如果它对应 `RCC_APB2ENR`，那么：

- 往这个地址写数据，就是在改 RCC 时钟配置
- 从这个地址读数据，就是在读当前 RCC 状态

所以寄存器经常看起来像变量，但它其实不是普通变量，而是映射到硬件上的特殊地址。

为什么寄存器又总是按“位”操作？

因为一个寄存器通常是 `32` 位，每一位或每几位都有独立含义。

所以你经常会看到：

```c
reg |=  (1 << n);   // 置位
reg &= ~(1 << n);   // 清零
```

本质上是在精确控制硬件功能。

最后用一句话压住：

在 `STM32F103VET6` 里，**寄存器就是 MCU 控制各个外设的“开关、旋钮和状态窗口”**。
你点灯、串口发送、定时中断、PWM 输出，最后本质上都是在读写寄存器。

### 方向一：用 `PC13` 点灯，把寄存器拆开讲

点灯本质上就是三步：

1. 先给 `GPIOC` 供时钟
2. 再把 `PC13` 设成输出
3. 最后输出高低电平

对应的关键寄存器如下：

- `RCC_APB2ENR`
  `APB2` 外设时钟开关，`IOPCEN=1` 后 `GPIOC` 才真正工作
- `GPIOC_CRH`
  配置 `PC8~PC15`。`PC13` 属于高 8 位引脚，所以在这里
- `GPIOC_ODR`
  直接保存输出电平
- `GPIOC_BSRR`
  写 `1` 置位，引脚输出高电平
- `GPIOC_BRR`
  写 `1` 复位，引脚输出低电平

最小代码：

```c
RCC->APB2ENR |= (1 << 4);
GPIOC->CRH &= ~(0xF << 20);
GPIOC->CRH |=  (0x2 << 20);
GPIOC->BRR = (1 << 13);
```

逐句理解：

- 第 1 句：打开 `GPIOC` 时钟
- 第 2 句：清掉 `PC13` 原来的 4 位配置
- 第 3 句：把 `PC13` 配成推挽输出
- 第 4 句：把 `PC13` 拉低

很多 `F103` 开发板上，`PC13` 对应的板载 LED 是低电平点亮，
因为常见接法是一端接 `VCC`，另一端接到 `PC13`。

所以会出现：

- `PC13 = 0`：LED 亮
- `PC13 = 1`：LED 灭

这不是程序写反了，而是硬件接法决定的。

### 方向二：寄存器 / 地址 / 位操作 / 数据手册 到底是什么关系

这条线的核心可以压成一句话：

**数据手册告诉你“这颗芯片有什么、某个引脚在不在”，参考手册告诉你“要控制它该改哪个寄存器、哪一位”；地址告诉你 CPU 去哪里访问；位操作告诉你怎样只改目标位。**

先说“内存映射”。

所谓内存映射，本质上是：

**把外设寄存器放进 CPU 可寻址的地址空间里。**

也就是说，CPU 访问：

- 某些地址是在访问 `Flash`
- 某些地址是在访问 `SRAM`
- 某些地址是在访问 `GPIO / RCC / USART` 这些外设寄存器

CPU 并不关心“这是内存还是 GPIO”，它只是在“访问某个地址”。

比如：

```c
RCC->APB2ENR |= (1U << 4);
```

其中：

- `1U << 4`：造出一个只在 `bit4` 为 `1` 的掩码
- `|=`：把这一位置 `1`，尽量不动其他位

而：

```c
GPIOC->CRH &= ~(0xFU << 20);
GPIOC->CRH |=  (0x2U << 20);
```

则是典型的“先清后设”：

1. 先清掉目标 4 位
2. 再把新的 4 位配置写进去

这背后是寄存器开发里最典型的“读-改-写”模式。

再说手册怎么查。

如果你要找 `GPIOC` 时钟使能：

1. 去参考手册找 `RCC`
2. 找 `APB2 peripheral clock enable register`
3. 找到 `RCC_APB2ENR`
4. 在位定义里找到 `IOPCEN`

如果你要找 `PC13` 模式配置：

1. 去参考手册找 `GPIO`
2. 找 `GPIOx_CRH`
3. 找 `MODE13[1:0]`
4. 找 `CNF13[1:0]`

于是代码就不是“背下来”的，而是从手册里“翻译出来”的。

### 3.1 为什么 `PC13` 对应 `CRH[23:20]`

在 STM32F1 里：

- `GPIOx_CRL` 管 `Px0 ~ Px7`
- `GPIOx_CRH` 管 `Px8 ~ Px15`

每个引脚都占 **4 位配置字段**。

`PC13` 属于 `8~15`，所以它在 `CRH` 里。

位偏移公式是：

```text
位偏移 = (引脚号 - 8) × 4
```

代入 `PC13`：

```text
(13 - 8) × 4 = 20
```

所以它的位段就是：

```text
CRH[23:20]
```

完整分组图如下：

```text
GPIOx_CRH  （控制 Px8 ~ Px15）

bit31                                                             bit0
+--------+--------+--------+--------+--------+--------+--------+--------+
| Px15   | Px14   | Px13   | Px12   | Px11   | Px10   |  Px9   |  Px8   |
|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|
+--------+--------+--------+--------+--------+--------+--------+--------+
 [31:28]  [27:24]  [23:20]  [19:16]  [15:12]   [11:8]    [7:4]    [3:0]
```

而 `PC13` 这 4 位又拆成：

- `CNF13[1:0]` 在 `23:22`
- `MODE13[1:0]` 在 `21:20`

`MODE13` 决定是不是输出、以及输出速度：

- `00`：输入模式
- `01`：输出模式，最高速度 `10MHz`
- `10`：输出模式，最高速度 `2MHz`
- `11`：输出模式，最高速度 `50MHz`

`CNF13` 在输入和输出模式下含义会变化。

如果要把 `PC13` 配成“通用推挽输出，2MHz”，就要写：

- `CNF13 = 00`
- `MODE13 = 10`

合起来就是：

```text
0010b
```

所以：

```c
GPIOC->CRH &= ~(0xF << 20);
GPIOC->CRH |=  (0x2 << 20);
```

的真正意思就是：

1. 清掉 `PC13` 的 4 位旧配置
2. 把 `PC13` 写成 `0010`
3. 也就是把它设为 `2MHz` 通用推挽输出

### 3.2 为什么“先清后写”是必须的

因为你改的是一个 **4 位字段**，不是 1 位。

如果原来这 4 位是：

```text
0110
```

你直接：

```c
|= 0010
```

结果仍然可能还是：

```text
0110
```

旧值里的 `1` 残留着，配置就错了。

所以标准套路永远是：

1. 先清字段
2. 再写字段

### 3.3 `RCC->APB2ENR` 最后到底落到哪里

典型定义链路是：

```c
#define PERIPH_BASE        ((uint32_t)0x40000000)
#define AHBPERIPH_BASE     (PERIPH_BASE + 0x00020000)
#define RCC_BASE           (AHBPERIPH_BASE + 0x00001000)   // = 0x40021000

typedef struct
{
    volatile uint32_t CR;        // 0x00
    volatile uint32_t CFGR;      // 0x04
    volatile uint32_t CIR;       // 0x08
    volatile uint32_t APB2RSTR;  // 0x0C
    volatile uint32_t APB1RSTR;  // 0x10
    volatile uint32_t AHBENR;    // 0x14
    volatile uint32_t APB2ENR;   // 0x18
} RCC_TypeDef;

#define RCC ((RCC_TypeDef *) RCC_BASE)
```

你可以把 `RCC` 理解成：

**“指向 RCC 这组寄存器排列表开头的结构体指针”**

于是：

```text
RCC->APB2ENR
≈ *(volatile uint32_t *)(0x40021000 + 0x18)
≈ *(volatile uint32_t *)0x40021018
```

所以：

```c
RCC->APB2ENR |= (1 << 4);
```

本质上就是去地址 `0x40021018` 上改某一位。

`volatile` 之所以重要，是因为它告诉编译器：

**这个地址背后连的是硬件，不要自作主张做危险优化。**

### 4.1 从 CPU 到 LED 亮灭的 ASCII 图

```text
[CPU执行语句]
       |
       v
[RCC->APB2ENR.IOPCEN = 1]
       |
       v
[GPIOC_CRH: MODE13=10, CNF13=00]
       |
       v
[CPU写输出寄存器]
   |---------------------------|
   |                           |
   v                           v
[GPIOC_BRR写BR13=1]      [GPIOC_BSRR写BS13=1]
   |                           |
   v                           v
[PC13 = 0V 低电平]        [PC13 = 3.3V 高电平]
   |                           |
   v                           v
[LED亮(常见低电平点亮)]   [LED灭]
```

这张图的意思非常直接：

1. 程序先执行某句控制 GPIO 的语句
2. `RCC` 保证 `GPIOC` 已经有时钟
3. `CRH` 把 `PC13` 配成输出
4. `BRR / BSRR` 改变 `PC13` 的输出电平
5. 最后电平变化反映到 LED 亮灭上

### 4.2 纯寄存器版最小闪烁程序

```c
#include "stm32f10x.h"

static void delay(volatile uint32_t n)
{
    while (n--) ;
}

int main(void)
{
    RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;

    GPIOC->CRH &= ~(GPIO_CRH_MODE13 | GPIO_CRH_CNF13);
    GPIOC->CRH |=  GPIO_CRH_MODE13_1;

    while (1)
    {
        GPIOC->BRR  = GPIO_BRR_BR13;
        delay(300000);

        GPIOC->BSRR = GPIO_BSRR_BS13;
        delay(300000);
    }
}
```

逐段翻译：

- `RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;`
  打开 `GPIOC` 时钟
- `GPIOC->CRH &= ~(GPIO_CRH_MODE13 | GPIO_CRH_CNF13);`
  清掉 `PC13` 的旧配置
- `GPIOC->CRH |= GPIO_CRH_MODE13_1;`
  把 `PC13` 设成 `2MHz` 通用推挽输出
- `GPIOC->BRR = GPIO_BRR_BR13;`
  把 `PC13` 拉低，很多板子此时 LED 亮
- `GPIOC->BSRR = GPIO_BSRR_BS13;`
  把 `PC13` 拉高，很多板子此时 LED 灭

为什么这里优先用 `BRR / BSRR`，而不是直接写 `ODR`？

因为它们更适合“只改单独一位”的场景：

- `BSRR`：置 `1`
- `BRR`：清 `0`

语义更直接，也更不容易误伤别的位。

**用户：**

### 5.1 把 `PC13` 闪灯改成 `PA0` 按键控制 LED

这里用一个最常见的假设：

- `PC13` 接板载 LED
- `PA0` 接按键
- `PA0` 采用内部上拉
- 按键按下时接地

最小代码如下：

```c
#include "stm32f10x.h"

static void delay(volatile uint32_t n)
{
    while (n--) ;
}

int main(void)
{
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN | RCC_APB2ENR_IOPCEN;

    GPIOC->CRH &= ~(GPIO_CRH_MODE13 | GPIO_CRH_CNF13);
    GPIOC->CRH |=  GPIO_CRH_MODE13_1;

    GPIOA->CRL &= ~(GPIO_CRL_MODE0 | GPIO_CRL_CNF0);
    GPIOA->CRL |=  GPIO_CRL_CNF0_1;
    GPIOA->ODR |=  GPIO_ODR_ODR0;

    while (1)
    {
        if ((GPIOA->IDR & GPIO_IDR_IDR0) == 0)
        {
            GPIOC->BRR = GPIO_BRR_BR13;
        }
        else
        {
            GPIOC->BSRR = GPIO_BSRR_BS13;
        }

        delay(1000);
    }
}
```

这次新增的知识点有：

- `GPIOA` 也要开时钟
- `PA0` 是输入脚，所以要改 `GPIOA_CRL`
- 输入脚的状态要从 `GPIOA->IDR` 里读
- 当使用“输入上拉/下拉模式”时，`ODR` 还会参与决定到底是“上拉”还是“下拉”

对于 `PA0` 来说：

- `PA0` 属于 `0~7`
- 所以它在 `GPIOA_CRL[3:0]`
- “输入上拉/下拉模式”的 4 位编码是 `1000b`

而：

```c
GPIOA->ODR |= GPIO_ODR_ODR0;
```

的真正意思是：

**在输入上拉/下拉模式下，选择“上拉”**

于是：

- 松开按键：`PA0 = 1`
- 按下按键：`PA0 = 0`

所以很多程序会写成：

```c
if ((GPIOA->IDR & (1 << 0)) == 0)
{
    // 按下
}
```

### 5.2 GPIOA / GPIOC 寄存器地址总览图

```text
GPIOA_BASE = 0x40010800
├─ CRL   +0x00  -> 0x40010800
├─ CRH   +0x04  -> 0x40010804
├─ IDR   +0x08  -> 0x40010808
├─ ODR   +0x0C  -> 0x4001080C
├─ BSRR  +0x10  -> 0x40010810
├─ BRR   +0x14  -> 0x40010814
└─ LCKR  +0x18  -> 0x40010818

GPIOC_BASE = 0x40011000
├─ CRL   +0x00  -> 0x40011000
├─ CRH   +0x04  -> 0x40011004
├─ IDR   +0x08  -> 0x40011008
├─ ODR   +0x0C  -> 0x4001100C
├─ BSRR  +0x10  -> 0x40011010
├─ BRR   +0x14  -> 0x40011014
└─ LCKR  +0x18  -> 0x40011018
```

这张图有一个非常重要的规律：

**GPIOA 和 GPIOC 的寄存器布局几乎完全一样，真正变化的只是基地址。**

所以读图时只要记住：

1. 先找端口基地址
2. 再加寄存器偏移
3. 最后看引脚位号

例如：

- `PC13` 的 `BRR`：`0x40011014`
- `PA0` 的 `IDR`：`0x40010808`

### 6.1 `GPIOx_CRL / GPIOx_CRH` 的完整分组图

```text
GPIOx_CRL  （控制 Px0 ~ Px7）

bit31                                                             bit0
+--------+--------+--------+--------+--------+--------+--------+--------+
|  Px7   |  Px6   |  Px5   |  Px4   |  Px3   |  Px2   |  Px1   |  Px0   |
|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|
+--------+--------+--------+--------+--------+--------+--------+--------+
 [31:28]  [27:24]  [23:20]  [19:16]  [15:12]   [11:8]    [7:4]    [3:0]

GPIOx_CRH  （控制 Px8 ~ Px15）

bit31                                                             bit0
+--------+--------+--------+--------+--------+--------+--------+--------+
| Px15   | Px14   | Px13   | Px12   | Px11   | Px10   |  Px9   |  Px8   |
|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|
+--------+--------+--------+--------+--------+--------+--------+--------+
 [31:28]  [27:24]  [23:20]  [19:16]  [15:12]   [11:8]    [7:4]    [3:0]
```

每个引脚的 4 位格式固定为：

```text
[ CNF1 CNF0 MODE1 MODE0 ]
```

所以：

- `PA0` 看 `GPIOA_CRL[3:0]`
- `PC13` 看 `GPIOC_CRH[23:20]`

### 6.2 把 `GPIOC->CRH` 那两句代码翻译成“地址 + 位图 + 动作”

来看：

```c
GPIOC->CRH &= ~(0xF << 20);
GPIOC->CRH |=  (0x2 << 20);
```

先还原真实地址：

```text
GPIOC_BASE = 0x40011000
CRH 偏移   = 0x04
GPIOC_CRH  = 0x40011004
```

所以这两句本质上是在改：

```text
0x40011004
```

而：

```text
0xF << 20
```

意味着：

```text
bit23 bit22 bit21 bit20
  1     1     1     1
```

也就是把 `PC13` 对应的 4 位整段选中。

再看：

```text
0x2 << 20
```

意味着：

```text
bit23 bit22 bit21 bit20
  0     0     1     0
```

也就是把 `PC13` 的 4 位写成：

```text
0010
```

整个过程可以只盯着 `PC13` 这一小段看：

```text
原来：xxxx
清零：0000
写入：0010
```

而：

- `23:22 = 00` -> `CNF13 = 00`
- `21:20 = 10` -> `MODE13 = 10`

含义就是：

**2MHz 通用推挽输出**

所以这两句代码的本质，就是把 `PC13` 从默认输入脚改造成“可以主动输出高低电平的推挽输出脚”。

### 7.1 STM32F1 常用 `CNF/MODE` 编码表

先记住总规则：

**当 `MODE=00` 时，引脚处于输入模式；当 `MODE!=00` 时，引脚处于输出或复用输出模式，此时 `CNF` 的含义会变化。**

`MODE` 编码：

```text
00 = 输入模式
01 = 输出模式，最高速度 10 MHz
10 = 输出模式，最高速度 2 MHz
11 = 输出模式，最高速度 50 MHz
```

输入类常见编码：

```text
0000 = 模拟输入
0100 = 浮空输入
1000 = 上拉/下拉输入
```

输出类常见编码：

```text
0010 = 通用推挽输出，2MHz
0110 = 通用开漏输出，2MHz
1010 = 复用推挽输出，2MHz
1110 = 复用开漏输出，2MHz

0001 = 通用推挽输出，10MHz
0101 = 通用开漏输出，10MHz
1001 = 复用推挽输出，10MHz
1101 = 复用开漏输出，10MHz

0011 = 通用推挽输出，50MHz
0111 = 通用开漏输出，50MHz
1011 = 复用推挽输出，50MHz
1111 = 复用开漏输出，50MHz
```

最值得直接背下来的几个值：

```text
0000 模拟输入
0100 浮空输入
1000 上拉/下拉输入
0010 通用推挽输出 2MHz
0001 通用推挽输出 10MHz
0011 通用推挽输出 50MHz
```

### 7.2 把 `PA0` 配成输入上拉

先看真实地址：

```text
GPIOA_BASE = 0x40010800
GPIOA_CRL = 0x40010800
GPIOA_IDR = 0x40010808
GPIOA_ODR = 0x4001080C
```

为什么 `PA0` 看 `CRL[3:0]`？

因为：

- `CRL` 管 `0~7`
- `PA0` 是第 `0` 号引脚

所以它就在：

```text
GPIOA_CRL[3:0]
```

如果把 `PA0` 配成“输入上拉/下拉模式”，那么：

- `MODE0 = 00`
- `CNF0 = 10`

合起来就是：

```text
1000b
```

但这里有一个 F1 里最容易忽略的点：

`1000b` 只表示“输入上拉/下拉模式”，真正是“上拉”还是“下拉”，还要看 `ODR0`：

- `ODR0 = 1`：上拉
- `ODR0 = 0`：下拉

所以最小代码片段是：

```c
RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;

GPIOA->CRL &= ~(0xF << 0);
GPIOA->CRL |=  (0x8 << 0);

GPIOA->ODR |=  (1 << 0);
```

这里最后一句不是“让 `PA0` 输出高电平”，而是在输入模式下告诉硬件：

**请选择内部上拉。**

### 8.1 为什么 `if (GPIOA->IDR & (1 << 0))` 能判断按键状态

先看地址：

```text
GPIOA_IDR = GPIOA_BASE + 0x08 = 0x40010808
```

所以：

```c
GPIOA->IDR
```

本质上就是在读地址 `0x40010808` 这个寄存器。

`IDR` 的位和引脚是这样对应的：

```text
bit15 ... bit3 bit2 bit1 bit0
 PA15 ... PA3  PA2  PA1  PA0
```

所以：

- `bit0` 对应 `PA0`
- `bit1` 对应 `PA1`
- ...

再看：

```c
(1 << 0)
```

会造出一个掩码：

```text
0000 0000 0000 0001
```

于是：

```c
GPIOA->IDR & (1 << 0)
```

就只会把 `bit0` 保留下来，其他位全清零。

比如：

```text
若 GPIOA->IDR = xxxx xxxx xxxx xxx1
结果        = 0000 0000 0000 0001   非0
```

说明 `PA0 = 1`

```text
若 GPIOA->IDR = xxxx xxxx xxxx xxx0
结果        = 0000 0000 0000 0000   等于0
```

说明 `PA0 = 0`

假设按键接法是“内部上拉，按下接地”，那么：

- 松开按键：`PA0 = 1`
- 按下按键：`PA0 = 0`

所以很多代码会明确写成：

```c
if ((GPIOA->IDR & (1 << 0)) == 0)
{
    // 按下
}
```

因为“低电平”就是“按下”。

### 8.2 STM32F1 GPIO 常用配置速查图

```text
场景                     4位编码   说明
------------------------------------------------------------
按键输入（内部上拉）     1000b     再把 ODR 置 1
按键输入（内部下拉）     1000b     再把 ODR 清 0
按键输入（浮空输入）     0100b     适合直接读取外部信号

LED 输出（推挽，2MHz）   0010b     最常见
LED 输出（推挽，10MHz）  0001b     也能用，但通常没必要

USART TX（复用推挽）     1011b     常见串口发送脚
USART RX（浮空输入）     0100b     常见串口接收脚

I2C 硬件引脚（复用开漏） 1111b     I2C 必须开漏
I2C 模拟 GPIO（开漏）    0110b     常见软件模拟 I2C
```

最容易混淆的 3 点：

1. `1000b` 不等于“已经上拉”
   它只是“上拉/下拉输入模式”，真正上拉还是下拉还要看 `ODR`
2. `USART TX` 和 `USART RX` 不是同一种配置
   `TX` 是复用输出，`RX` 是输入
3. `I2C` 必须开漏
   不管硬件 I2C 还是很多软件模拟 I2C，核心都离不开“开漏 + 上拉”
