## 2. 什么是寄存器

一句话先说清楚：

**寄存器就是芯片内部一小块“有固定用途、可直接读写”的高速存储单元。**

在 STM32 里，寄存器通常分两类：

- **内核寄存器**
  例如 Cortex-M3 的 `R0 ~ R15`、`SP`、`PC`。它们主要给 CPU 执行指令时使用。
- **外设寄存器**
  例如 GPIO、RCC、USART、TIM 的各种控制寄存器。单片机开发里最常说的“操作寄存器”，基本都指这一类。

你可以把外设寄存器理解成芯片里各个硬件模块的“控制面板”：

- 某一位置 `1`：打开某个功能
- 某几位写成某个编码：设置工作模式
- 读某一位：查看当前状态

所以：

**写寄存器 = 给硬件下命令**

**读寄存器 = 看硬件当前状态**

## 3. 寄存器、地址、位操作、手册之间的关系

这四个概念可以压成一句话：

**外设寄存器就是映射到固定地址上的控制单元，CPU 通过地址访问它们，再用位操作精确改动某几位；数据手册告诉你“芯片有什么”，参考手册告诉你“这些东西怎么配”。**

### 3.1 什么是内存映射

STM32 采用的是 **内存映射 I/O**。

也就是说，外设寄存器也被放进了 CPU 的统一地址空间里：

- 有些地址连到 `Flash`
- 有些地址连到 `SRAM`
- 有些地址连到 `GPIO / RCC / USART` 这些外设寄存器

CPU 并不关心某个地址背后是 RAM 还是 GPIO，它只是“按地址读写”。

例如：

```c
RCC->APB2ENR |= (1 << 4);
```

表面上像是在改一个 C 变量，实际上是在访问某个固定硬件地址上的寄存器位。

### 3.2 为什么寄存器总要按位操作

因为一个寄存器通常是 `32` 位，而这 `32` 位经常被多个功能共享。

例如：

```text
bit31 ... bit4 bit3 bit2 bit1 bit0
                功能A 功能B 状态C 使能D
```

如果你整块乱写，很容易把别的功能一起改坏，所以寄存器操作最常见的就是：

```c
reg |=  (1 << n);   // 把第 n 位置 1
reg &= ~(1 << n);   // 把第 n 位清 0
```

### 3.3 数据手册和参考手册怎么分工

- **数据手册 Datasheet**
  主要看芯片资源、封装、引脚、电气参数、复用功能。
- **参考手册 Reference Manual**
  主要看外设寄存器地址、位定义、配置流程和工作机制。

可以简单记：

- **数据手册回答“有什么”**
- **参考手册回答“怎么配”**

## 4. 以 PC13 点灯讲清楚寄存器在干什么

用 `STM32F103VET6` 上常见的 `PC13` 板载 LED 为例，点灯本质上只有 3 步：

1. 打开 `GPIOC` 时钟
2. 把 `PC13` 配成输出
3. 让 `PC13` 输出高电平或低电平

### 4.1 最小代码

```c
#include "stm32f10x.h"

int main(void)
{
    RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;

    GPIOC->CRH &= ~(0xF << 20);
    GPIOC->CRH |=  (0x2 << 20);

    while (1)
    {
        GPIOC->BRR  = (1U << 13);
        for (volatile int i = 0; i < 500000; ++i);

        GPIOC->BSRR = (1U << 13);
        for (volatile int i = 0; i < 500000; ++i);
    }
}
```

### 4.2 每个寄存器分别做什么

- `RCC->APB2ENR`
  打开 APB2 外设时钟，这里最关心的是 `IOPCEN` 位。
- `GPIOC->CRH`
  配置 `PC8 ~ PC15` 的工作模式，`PC13` 的配置就在这里。
- `GPIOC->ODR`
  输出数据寄存器，保存“想输出的电平”。
- `GPIOC->IDR`
  输入数据寄存器，读取“当前引脚真实电平”。
- `GPIOC->BSRR`
  位设置寄存器，写 `1` 到某位表示置高。
- `GPIOC->BRR`
  位复位寄存器，写 `1` 到某位表示清零，也就是拉低。

### 4.3 为什么必须先开时钟

如果时钟没开，`GPIOC` 外设内部逻辑通常并没有正常工作。

所以：

```c
RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;
```

这一步可以理解成：**先给 `GPIOC`“通电”，再谈配置。**

### 4.4 为什么很多板子上 PC13 是低电平点亮

很多 `STM32F103` 开发板的 LED 接法是：

```text
3.3V -> 电阻 -> LED -> PC13
```

于是：

- `PC13 = 0`：电流流入芯片，LED 亮
- `PC13 = 1`：两端压差变小，LED 灭

所以很多板子上的 `PC13` 是：

**低电平点亮，高电平熄灭**

## 5. 从头文件一路追到真实地址

像下面这种写法：

```c
RCC->APB2ENR |= (1 << 4);
```

本质上只是：

**去访问某个固定地址上的 32 位寄存器。**

典型定义链路大概是这样：

```c
#define PERIPH_BASE        ((uint32_t)0x40000000)
#define AHBPERIPH_BASE     (PERIPH_BASE + 0x00020000)
#define RCC_BASE           (AHBPERIPH_BASE + 0x00001000)   // 0x40021000

typedef struct
{
    volatile uint32_t CR;        // 0x00
    volatile uint32_t CFGR;      // 0x04
    volatile uint32_t CIR;       // 0x08
    volatile uint32_t APB2RSTR;  // 0x0C
    volatile uint32_t APB1RSTR;  // 0x10
    volatile uint32_t AHBENR;    // 0x14
    volatile uint32_t APB2ENR;   // 0x18
} RCC_TypeDef;

#define RCC ((RCC_TypeDef *) RCC_BASE)
```

于是：

```text
RCC->APB2ENR
≈ *(volatile uint32_t *)(0x40021000 + 0x18)
≈ *(volatile uint32_t *)0x40021018
```

### 5.1 `volatile` 为什么重要

寄存器背后连的是硬件，不是普通内存。  
如果没有 `volatile`，编译器可能会错误优化读写过程。

所以 `volatile` 可以通俗理解成：

**告诉编译器，这个地址很特殊，每次都必须老老实实去读写。**

## 6. GPIOA / GPIOC 寄存器地址总览

```text
GPIOA_BASE = 0x40010800
├─ CRL   +0x00  -> 0x40010800
├─ CRH   +0x04  -> 0x40010804
├─ IDR   +0x08  -> 0x40010808
├─ ODR   +0x0C  -> 0x4001080C
├─ BSRR  +0x10  -> 0x40010810
├─ BRR   +0x14  -> 0x40010814
└─ LCKR  +0x18  -> 0x40010818

GPIOC_BASE = 0x40011000
├─ CRL   +0x00  -> 0x40011000
├─ CRH   +0x04  -> 0x40011004
├─ IDR   +0x08  -> 0x40011008
├─ ODR   +0x0C  -> 0x4001100C
├─ BSRR  +0x10  -> 0x40011010
├─ BRR   +0x14  -> 0x40011014
└─ LCKR  +0x18  -> 0x40011018
```

读图方法只有三步：

1. 先找端口基地址
2. 再加寄存器偏移
3. 最后看具体引脚对应哪一位

例如：

- `GPIOC_BRR = 0x40011014`
- `GPIOA_IDR = 0x40010808`

## 7. CRL / CRH 为什么每 4 位控制一个引脚

在 `STM32F1` 里，GPIO 配置寄存器不是“一脚一位”，而是：

**一脚 4 位**

```text
GPIOx_CRL  （控制 Px0 ~ Px7）

bit31                                                             bit0
+--------+--------+--------+--------+--------+--------+--------+--------+
|  Px7   |  Px6   |  Px5   |  Px4   |  Px3   |  Px2   |  Px1   |  Px0   |
|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|
+--------+--------+--------+--------+--------+--------+--------+--------+
 [31:28]  [27:24]  [23:20]  [19:16]  [15:12]   [11:8]    [7:4]    [3:0]

GPIOx_CRH  （控制 Px8 ~ Px15）

bit31                                                             bit0
+--------+--------+--------+--------+--------+--------+--------+--------+
| Px15   | Px14   | Px13   | Px12   | Px11   | Px10   |  Px9   |  Px8   |
|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|CNF+MODE|
+--------+--------+--------+--------+--------+--------+--------+--------+
 [31:28]  [27:24]  [23:20]  [19:16]  [15:12]   [11:8]    [7:4]    [3:0]
```

每个引脚的 4 位固定格式是：

```text
[ CNF1 CNF0 MODE1 MODE0 ]
```

所以：

- `PA0` 看 `GPIOA_CRL[3:0]`
- `PC13` 看 `GPIOC_CRH[23:20]`

## 8. 把 `GPIOC->CRH` 的两句代码翻译成地址 + 位图 + 硬件动作

来看这两句：

```c
GPIOC->CRH &= ~(0xF << 20);
GPIOC->CRH |=  (0x2 << 20);
```

### 8.1 它们操作的是哪个真实地址

```text
GPIOC_BASE = 0x40011000
CRH 偏移   = 0x04
GPIOC_CRH  = 0x40011004
```

所以这两句代码实际上都在改地址：

```text
0x40011004
```

### 8.2 `0xF << 20` 和 `0x2 << 20` 是哪几位

`PC13` 在 `CRH` 里对应的字段是 `[23:20]`。

所以：

```text
0xF << 20  -> 1111 放到 bit23:20
0x2 << 20  -> 0010 放到 bit23:20
```

位图上可以只看 `PC13` 这 4 位：

```text
原来：xxxx
清零：0000
写入：0010
```

### 8.3 为什么这是在改 `PC13` 的 `CNF13/MODE13`

对 `PC13` 来说：

- `23:22` 是 `CNF13`
- `21:20` 是 `MODE13`

`0010` 拆开就是：

- `CNF13 = 00`
- `MODE13 = 10`

含义就是：

**2MHz 通用推挽输出**

### 8.4 为什么必须先清后写

因为改的是 4 位位段，不是 1 位。  
如果只 `OR` 不先清零，旧值中的 `1` 可能残留下来，导致配置错误。

## 9. STM32F1 常用 GPIO `CNF/MODE` 编码表

先记住：

**当 `MODE=00` 时是输入模式；当 `MODE!=00` 时是输出或复用输出模式，此时 `CNF` 的含义会变化。**

### 9.1 `MODE` 编码

```text
00 = 输入模式
01 = 输出模式，最高速度 10 MHz
10 = 输出模式，最高速度 2 MHz
11 = 输出模式，最高速度 50 MHz
```

### 9.2 输入模式常见编码

```text
0000 = 模拟输入
0100 = 浮空输入
1000 = 上拉/下拉输入
```

### 9.3 输出模式常见编码

```text
0010 = 通用推挽输出，2MHz
0110 = 通用开漏输出，2MHz
1010 = 复用推挽输出，2MHz
1110 = 复用开漏输出，2MHz

0001 = 通用推挽输出，10MHz
0101 = 通用开漏输出，10MHz
1001 = 复用推挽输出，10MHz
1101 = 复用开漏输出，10MHz

0011 = 通用推挽输出，50MHz
0111 = 通用开漏输出，50MHz
1011 = 复用推挽输出，50MHz
1111 = 复用开漏输出，50MHz
```

### 9.4 最值得直接背下来的几个值

```text
0000 模拟输入
0100 浮空输入
1000 上拉/下拉输入
0010 通用推挽输出 2MHz
0001 通用推挽输出 10MHz
0011 通用推挽输出 50MHz
```

## 10. 把 PA0 配成输入上拉

### 10.1 真实地址

```text
GPIOA_BASE = 0x40010800
GPIOA_CRL = 0x40010800
GPIOA_IDR = 0x40010808
GPIOA_ODR = 0x4001080C
```

### 10.2 为什么 `PA0` 看 `CRL[3:0]`

因为：

- `CRL` 管 `0~7`
- `CRH` 管 `8~15`

而 `PA0` 是第 `0` 号引脚，所以它的配置位就是：

```text
GPIOA_CRL[3:0]
```

### 10.3 为什么输入上拉是 `1000b`

`PA0` 配成输入上拉/下拉模式时：

- `MODE0 = 00`
- `CNF0 = 10`

所以：

```text
CNF0 MODE0 = 10 00 = 1000b
```

### 10.4 为什么还要把 `ODR0` 置 1

这里是 F1 初学者最容易忽略的点：

`1000b` 只表示“输入上拉/下拉模式”，到底是上拉还是下拉，还要看 `ODR0`：

- `ODR0 = 1`：上拉
- `ODR0 = 0`：下拉

也就是说：

```c
GPIOA->ODR |= (1 << 0);
```

在这里不是“输出高电平”，而是在输入模式下告诉硬件：

**请选择内部上拉。**

### 10.5 最小代码片段

```c
RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;

GPIOA->CRL &= ~(0xF << 0);
GPIOA->CRL |=  (0x8 << 0);

GPIOA->ODR |=  (1 << 0);
```

## 11. 为什么 `if (GPIOA->IDR & (1 << 0))` 能判断按键状态

假设按键接法是：

- `PA0` 配成内部上拉输入
- 按键按下时把 `PA0` 接到 `GND`

那硬件行为就是：

- 松开按键：`PA0 = 1`
- 按下按键：`PA0 = 0`

### 11.1 这句代码在二进制层面干了什么

```c
GPIOA->IDR & (1 << 0)
```

右边的：

```c
(1 << 0)
```

会生成一个掩码：

```text
0000 0000 0000 0001
```

按位与以后，只保留 `bit0`：

```text
若 GPIOA->IDR = xxxx xxxx xxxx xxx1
结果        = 0000 0000 0000 0001   非0

若 GPIOA->IDR = xxxx xxxx xxxx xxx0
结果        = 0000 0000 0000 0000   等于0
```

而 `IDR` 的 `bit0` 正好对应 `PA0`，所以：

- 结果非 0：`PA0` 是高电平
- 结果等于 0：`PA0` 是低电平

### 11.2 为什么很多代码写 `== 0` 判断按下

因为在“内部上拉、按下接地”的常见接法里：

- 松开 = `1`
- 按下 = `0`

所以很多代码会明确写成：

```c
if ((GPIOA->IDR & (1 << 0)) == 0)
{
    // 按键按下
}
```

## 12. GPIO 常用配置速查

```text
场景                     4位编码   说明
------------------------------------------------------------
按键输入（内部上拉）     1000b     再把 ODR 置 1
按键输入（内部下拉）     1000b     再把 ODR 清 0
按键输入（浮空输入）     0100b     适合直接读取外部驱动信号

LED 输出（推挽，2MHz）   0010b     最常见，够用也直观
LED 输出（推挽，10MHz）  0001b     也能用，但通常没必要

USART TX（复用推挽）     1011b     常见串口发送脚
USART RX（浮空输入）     0100b     常见串口接收脚

I2C 硬件引脚（复用开漏） 1111b     I2C 必须开漏
I2C 模拟 GPIO（开漏）    0110b     常见软件模拟 I2C
```

### 12.1 最容易混淆的 3 点

1. `1000b` 不等于“已经上拉”
   它只是“上拉/下拉输入模式”，真正上拉还是下拉还要看 `ODR`。
2. `USART TX` 和 `USART RX` 不是同一种配置
   `TX` 是复用输出，`RX` 是输入。
3. `I2C` 必须开漏
   无论硬件 I2C 还是很多软件模拟 I2C，核心都离不开“开漏 + 上拉”。

## 13. 一条最实用的学习路线

如果你是第一次学 STM32 寄存器开发，可以按这个顺序看：

1. 先理解什么是寄存器
2. 再理解“地址 + 偏移 = 真地址”
3. 再理解 `CRL / CRH` 的 4 位分组规则
4. 再记住最常用的几个 `CNF/MODE` 编码
5. 然后用两个最经典的例子反复练：
   - `PC13` 点灯
   - `PA0` 按键输入

这两个例子打通以后，再去学：

- 串口
- 定时器
- PWM
- EXTI 外部中断
- I2C / SPI

就会顺很多。
